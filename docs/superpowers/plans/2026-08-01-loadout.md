# Loadout CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `loadout` Python CLI that resolves named loadouts from this repo, vendors rules/skills into consumer projects, and enforces lockfile-backed drift checks.

**Architecture:** A uv-packaged CLI (`src/loadout/`) fetches a pinned loadout source (git or `LOADOUT_PATH`), resolves composable YAML loadouts with include/exclude, validates rule/skill contracts, then atomically writes vendored files plus managed blocks in `AGENTS.md` / `CLAUDE.md` and a JSON lockfile. Content (`rules/`, `skills/`, `loadouts/`) lives beside the tool so `uvx --from git+…@ref` always version-matches instructions.

**Tech Stack:** Python 3.12+, uv, click (or typer), PyYAML, pytest, just

## Global Constraints

- Package name: `loadout`; CLI entrypoint: `loadout`
- Skills vendored only under `skills_dir` (default `.claude/skills`); never create `.agents/skills/` or `.cursor/skills/` unless manifest overrides `skills_dir`
- Sync excludes skill-root `evals/`; skip junk: `__pycache__/`, `node_modules/`, `*.pyc`, `.DS_Store`
- Exit codes: 0 success / check clean; 1 check drift; 2 validation; 3 network/auth
- Generated header injected into rule `.mdc` and `SKILL.md` only, after YAML frontmatter
- Cookiecutter hooks (spec §8) live in the metafactory template repo — document the contract here; do not implement the template in this repo
- Acceptance criterion 18 is a manual smoke test on real Cursor/Claude Code — document in README; not automated

### Task 4: Source fetch (`LOADOUT_PATH` + git cache)

**Files:**
- Create: `src/loadout/fetch.py`
- Test: `tests/test_fetch.py`

**Interfaces:**
- Consumes: Manifest
- Produces: `FetchedSource(root: Path, resolved_sha: str, from_local: bool)`
- `fetch_source(manifest, lock: Lockfile | None, *, env=os.environ) -> FetchedSource`
  - If `LOADOUT_PATH` set: use that dir, `resolved_sha="local"`
  - Else if lock exists and `lock.ref == manifest.ref`: fetch at `lock.resolved_sha`
  - Else: resolve `ref` to SHA, shallow clone/fetch into cache `~/.cache/loadout/sources/<sha>/`
  - Network failures → `FetchError` (exit 3)

### Task 9: Sync and sync --check

**Files:**
- Create: `src/loadout/sync.py`
- Test: `tests/test_sync.py`

**Interfaces:**
- `sync(project_root: Path, *, check: bool = False) -> SyncResult`
  1. Load manifest (+ optional lock)
  2. Fetch source
  3. Resolve + validate
  4. If check: compare on-disk managed files + block hashes to lock/expected; DriftError on mismatch; for `resolved_sha=="local"`, warn on SHA mismatch instead of failing SHA check
  5. Else: prune files in old lock not in new set (only those listed); write files; splice blocks; write lock; print summary
- Idempotent: second sync → zero file changes
- Summary: added/updated/removed/unchanged + block change flags + note about Cursor reload / Claude restart
